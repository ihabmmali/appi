# Architecture

Read goals, current architecture, relevant source/ADRs and task constraints.

1. Compare alternatives, costs, migration, compatibility and reversibility.
2. Create `docs/decisions/<ID>.md` using [TEMPLATES.md](TEMPLATES.md), initially proposed.
3. Record acceptance authority and decision evidence. Reuse existing authorization; never invent approval.
4. Update decision record → ARCHITECTURE once accepted (mark implementation gaps) → implementation task(s) and architecture task evidence → index/release plan → state if changed.
5. Validate records and review intended versus implemented behavior.

Allowed outputs are decisions, architecture and linked task specifications. Source refactoring needs an implementation assignment. Superseding decisions retain links and prior rationale. Completion requires a clear decision status and consequences; a proposal may remain open awaiting a material decision.
